Урок 3. Снапшот-тестирование

Вручную проверять весь UI после каждого изменения — долго и дорого. Для автоматизации таких регрессионных проверок используют методы снапшот-тестирования.
Часто термины «снапшот-тестирование» (Snapshot Testing) и «скриншот-тестирование» (Screenshot Testing) ошибочно считают синонимами, однако важно понимать их различие.

1. Снапшот-тестирование — это общий подход, при котором создается «слепок» (snapshot) состояния и сравнивается с эталоном. При этом слепок не обязательно является изображением. 
Это может быть текстовое представление UI-иерархии, JSON-объект состояния или HTML-разметка.
2. Скриншот-тестирование (или визуальная регрессия) — это конкретный тип снапшот-тестирования. Здесь в качестве «слепка» выступает растровое изображение (чаще всего PNG), 
а сравнение с эталоном происходит попиксельно.

Этот способ незаменим для поиска визуальных отклонений: он выявляет, когда изменение в коде неожиданно «ломает» внешний вид, хотя функционально все может по-прежнему работать.

- Процесс скриншот-тестирования делится на два этапа.
1. Создание эталона. Компонент отрисовывается, с него делается скриншот и сохраняется в репозиторий. Это происходит один раз при настройке теста или каждый раз, 
когда UI целенаправленно меняется.
2. Запуск теста. Компонент отрисовывается снова. Полученный «актуальный» скриншот попиксельно сравнивается с «эталонным».
Результат сравнения может быть двух видов.
- Тест пройден — изображения полностью идентичны.
- Тест провален — обнаружены отличия. В этом случае система генерирует «дифф» (diff) — специальный файл, где наглядно подсвечены все не совпадающие области.

Этот метод идеально подходит для выявления визуальных регрессий — багов, которые не ломают логику, но портят пользовательский опыт. Например, он отловит ситуации, когда:
- у кнопки «поехали» отступы после обновления библиотеки компонентов;
- текст начал некорректно переноситься на новую строку;
- вместо иконки отображается пустое место;
- цвет элемента изменился из-за конфликта стилей;
- неожиданно изменился размер шрифта;
- элемент «съехал» при определенном наполнении контентом.

Для реализации этого подхода можно использовать несколько инструментов, каждый из которых имеет свою специфику:
- iOS (нативная разработка) — swift-snapshot-testing. Это классическая снапшот-библиотека. 
Инструмент позволяет создавать «слепки» любых данных, например, текстовое представление иерархии view (аналог recursiveDescription).
- Android (нативная разработка) — paparazzi. Этот инструмент, напротив, сфокусирован именно на скриншот-тестировании.

Кросс-платформенная автоматизация: Appium (есть репозиторий на GitHub) полезен для открытия конкретного экрана приложения, 
а библиотека Pillow может использоваться для попиксельного сравнения изображений.


Проверка
Вопрос 1. Что проверяют при тестировании поля ввода с паролем?
Верный ответ: D) Все варианты верны.

Вопрос 2. Какой элемент интерфейса наиболее вероятно будет конфликтовать с Tab Bar в iOS или Bottom Navigation в Android?
Верный ответ: A) Кнопка Принять в нижней части экрана.

Вопрос 3. Какой жест в iOS используется для навигации «назад»?
Верный ответ: C) Свайп от левого края экрана.

Вопрос 4. Как проверить работу жестов на разных устройствах?
Верный ответ: C) На реальных устройствах и эмуляторах.

Вопрос 5. Что проверяет скриншот-тестирование?
Верный ответ: B) Соответствие визуального представления эталону.

Вопрос 6. Что такое «дифф» в скриншот-тестировании?
Верный ответ: A) Разница между эталонным и текущим скриншотом.

Вопрос 7. При нажатии на поле ввода и попытке что-то ввести ничего не происходит. В чем может быть причина?
Верный ответ: A) Поле ввода в неактивном состоянии.

Вопрос 8. После обновления цветов в приложении кнопка Удалить стала серого цвета вместо красного. Какой вид тестов помог бы отловить эту ошибку?
Верный ответ: B) Cкриншот-тесты.
